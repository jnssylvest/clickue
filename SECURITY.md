# Security

> [!IMPORTANT]
> **Clickue is vibe-coded and was developed with substantial AI assistance.** Caution was taken
> during development, but AI-assisted development does not guarantee bug-free or secure
> software. Review the source and use normal precautions. Test automations safely, protect
> notification credentials, and avoid unattended use for consequential actions.

Clickue clicks, types and presses keys in other programs, and can send optional phone alerts
over the internet. This page says what has been done to make that safe, what hasn't, and how
to report a problem.

## Reporting a problem

Please **don't** put security problems in a public issue.

- Use GitHub's private reporting: the repository's **Security** tab → **Report a
  vulnerability** (if that button isn't there, open a short public issue that only says you'd
  like to report a security problem privately, without any details, and you'll be contacted).
- Include the Clickue version (☰ Menu → About), what you did, what happened, and what you
  expected. **Never** include real webhook URLs, bot tokens, passwords or screenshots of them.

Only the latest release gets fixes.

## What was reviewed (version 4.5)

A threat review of the existing code and the new features covered the areas below. Each item
found was fixed, and regression tests were added (`tests/test_workflows.py`,
`tests/check_release.py`).

| Area | What Clickue does now |
|---|---|
| **Update checks (4.6)** | Optional (Preferences → General, on by default); off = no connection for updates at all. Only `https://api.github.com/repos/jnssylvest/clickue/releases/latest` and, when you choose to upgrade, the release's files on `github.com` (redirects followed only to GitHub's download hosts, at most 5). HTTPS with certificate and host-name checks (4.6.1: against Windows' certificate store plus the bundled `certifi` list of trusted root certificates; checks are never turned off), 20-second timeouts, size limits (512 KB for the release description, 400 MB for a download). Only download links on `https://github.com/` from that release are used. The download must match the release's `SHA256SUMS.txt` or it's deleted. That proves it's the file the release lists, not who made it: the files aren't code-signed, and someone who could change the GitHub release could change both. The installer runs with fixed arguments; a portable upgrade only takes `Clickue.exe` out of the zip. A backup of your jobs is made first |
| **Phone alerts** | Sends only to `https://discord.com/api/webhooks/…` (and the discordapp.com / ptb / canary hosts) and `https://api.telegram.org/bot…`. Other schemes, hosts, ports, user-info and paths are refused when saving and when sending. HTTPS with certificate and host-name checks; redirects are not followed; 10-second timeout; at most 64 KB of the response is read; at most one alert per 2 s and 60 per hour per service; sent in the background so failures never stall automation. The Telegram token goes in the HTTPS request, never in logs. Before: any URL (including `file://`) was accepted and redirects were followed |
| **Secrets** | Webhook URL, bot token and chat id are masked in Preferences, redacted from every log line and error message, and **left out of backups** (before: copied into every daily backup). Optional encryption with the Windows account (DPAPI). Type / Paste text is never written to logs, click history, run history or error messages; **Secret** steps are encrypted with DPAPI, hidden in the timeline, blacked out in videos, and never exported |
| **Imports and backups** | Treated as untrusted: size limit (50 MB), schema version check, every field type-checked and clamped, unknown fields and step types dropped, pictures checked (valid PNG, at most 8000 × 8000, decompression-bomb limit), step lists and paths limited. Imported jobs arrive **stopped** with a summary of steps that send keyboard input. Nothing in a jobs file is executed; there is no code, script or plugin step |
| **Files** | Data stays in the data folder. Video and screenshot file names are generated by Clickue (job names are reduced to letters, digits, `-` and `_`). Clean-up only deletes files whose names match Clickue's own patterns, in one folder, never in subfolders |
| **Uninstall / clean-up** | The only recursive delete checks first that the folder really is Clickue's data folder (name, not a drive or home folder, contains Clickue's files). Deleting data is always the user's explicit choice. The installer's uninstaller only deletes `%APPDATA%\Clickue`, and removes the start-with-Windows entry only if it points at that installation |
| **Input safety** | One input queue (before: a manual test click could send input at the same time as a scheduled job). Emergency-stop hotkey. Held keys and buttons are released whenever a run ends and at exit. Time limits on every wait, loop and run; at most 200,000 steps per run. Pause all pauses a running job between steps. Targets are verified before clicking and never silently replaced by an unverified position |
| **Recorder** | Recording is visible (red bar), only while you record, ignores Clickue's own windows and injected input, and keeps events in memory until you save. It warns that typed passwords would be recorded |
| **Screen video** | Off by default, per job, visible indicator, local only, hidden areas, blacked out during text entry, retention by age and size, stops (without stopping the job) on low disk space or errors |
| **Code** | No `eval`, `exec`, `pickle` or `shell=True`; the only subprocesses are the installer's uninstaller, the portable self-delete and (4.6, when you choose to upgrade) the checksum-checked new installer or new `Clickue.exe`, all with fixed, validated arguments. Adapters (ways to find targets) are part of the program; Clickue never loads code from files or the internet |
| **Dependencies** | Minimum versions include known security fixes (e.g. Pillow ≥ 12.3.0). `certifi` (4.6.1) supplies the trusted root certificates bundled into the exe; a newer list arrives with each Clickue version. The build checks them with `pip-audit` |
| **Build and release** | The workflow is read-only by default; only the release job (pushes to `main`, never pull requests) can write releases. Actions are pinned to exact commits, checkout doesn't keep credentials, and no secrets are used besides the automatic `GITHUB_TOKEN`. Each release includes SHA-256 checksums |

## Automated checks

Every push and pull request runs, on Windows:

- the headless test suites (`tests/test_*.py`) and `tests/check_release.py` (links, disclosure,
  no secrets or private details in public files, workflow permissions, uninstall boundaries),
- `pip-audit` on `requirements.txt` (known vulnerable dependency versions fail the build),
- `bandit` static analysis of `src/` (high-severity findings fail the build).

Passing these checks does **not** prove Clickue is secure; they catch known kinds of mistakes.

## Known limits and remaining risks

- **Clickue is not professionally audited or certified.** The review above was done with AI
  assistance and has the limits of any review.
- **It acts with your permissions.** Anything you can click or type, a job can too. A badly
  set-up or imported job can do damage; test with Dry run and Step through, and keep a person
  in charge of consequential actions.
- **Unsigned executable.** Windows SmartScreen warns about it; download only from the Releases
  page and compare the checksum.
- **Plain-text data by default.** Jobs (including non-secret typed text and saved pictures of
  your screen) and, unless you turn protection on, alert credentials are stored unencrypted in
  your user profile, readable by programs running as you.
- **Screen content.** Saved pictures, videos and failure screenshots can show whatever was on
  screen. They stay local, but treat backups, exports and videos as private.
- **Recording captures keystrokes** while it runs, as designed. Don't type secrets while
  recording.
- **Windows features it relies on** (DPAPI, clipboard history exclusion, input hooks) behave as
  Windows documents them; other software on the PC (e.g. clipboard managers, security tools)
  may still see or block what Clickue does.
- **Not yet verified on every Windows setup.** The automated tests fake the screen, mouse and
  keyboard; real-desktop behaviour is checked by hand.
